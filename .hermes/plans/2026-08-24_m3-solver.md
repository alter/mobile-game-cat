### Task 1: Pin down the shared JSON level format

**Objective:** A written schema both implementations agree on.

**Files:**
- Create: `tools/solver/level_format.md` (short spec) and `tools/solver/schema.py` (dataclasses + load/save)

**Format (matches C# `Level`/`PileEntry`):**
```json
{
  "number": 1,
  "room_id": "room_01",
  "moves_limit": 33,
  "pile": [
    {"id": 1, "kind": "vase", "blocked_by": [2]},
    {"id": 2, "kind": "book", "blocked_by": []}
  ]
}
```
Rules: ids unique ints; `blocked_by` references existing ids; no cycles (validated); kinds drawn from a per-level kind set sized so triples are completable.

**Step 1:** Write `schema.py`: `PileItem`, `LevelDef` dataclasses, `load_level(path)`, `save_level(level, path)`, `validate(level)` raising `ValueError` on duplicate ids / unknown blocked_by refs / cycles (topological check).
**Step 2:** pytest tests: valid round-trip; duplicate id raises; dangling ref raises; cycle raises.
**Step 3:** Commit: `M3: level format schema + validation`.

### Task 2: Rules mirror in Python (3.1)

**Objective:** Python replays the same rules as C# `Board`.

**Files:**
- Create: `tools/solver/rules.py`
- Test: `tools/tests/test_rules.py`

Mirror of `game/Assets/Core/Board.cs` semantics exactly:
- available(item) = not taken AND all `blocked_by` taken
- take → place on shelf (leftmost free slot); triple match removes 3
- full shelf after placement with no match → `shelf_jammed`
- pile emptied → `win` (winning take consumes no move)
- else moves_left−1; if 0 and pile remains → `out_of_moves`

**Step 1:** Failing tests first: empty pile availability, three-layer stack, circular block, match across row boundary, full-shelf jam, win/out_of_moves/jam outcomes, move counter behavior (copy acceptance cases from `game/Tests/Core/BoardTests.cs`).

**Step 3:** Cross-check harness `tools/tests/conformance_test.py`: generate N=30 random solvable levels (Task 4 helper), solve each in Python writing a solution script (`[item_id,...]` order), replay the same order through a tiny C# console runner, assert same outcome and same moves count.

### Task 3: Solver — solvable? in how many moves? (3.2)

**Objective:** `solve(level) -> Solution | None` under 2 s per level.

**Files:**
- Create: `tools/solver/solver.py`
- Test: `tools/tests/test_solver.py`

Algorithm:
- State: (frozenset of taken ids, shelf tuple). Memoize visited states.
- Move ordering heuristic: prefer taking an item whose kind already has 2 on the shelf, then 1, then 0; this keeps branching low.
- BFS over states (fewest moves first) with the heuristic ordering inside each expansion; cap explored states (e.g. 200k) — report `None` (treated as dead end) if exceeded.
- Return: solvable flag, minimal move count, one concrete move sequence.

**Step 1:** Tests: 5 known-solvable hand-built levels all return solutions; 5 known-dead-end levels (e.g. pile with an odd count of a kind buried under blocking layers such that shelf jams) return None; timing assertion < 2 s on a realistic 40-item level.
**Step 2:** Implement, iterate until green and fast enough.
**Step 3:** Commit: `M3: state-search solver with memoization`.

Generator:
