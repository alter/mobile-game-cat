# How this broke, and why it was predicted

## Symptom

Four tests error, all in `tools/tests/conformance_test.py`:

```
FAILED test_locked_level_solution_agrees  - subprocess.CalledProcessError
ERROR  test_csharp_and_python_agree       - subprocess.CalledProcessError
ERROR  test_booster_recovery_agrees       - subprocess.CalledProcessError
ERROR  test_locked_items_agree            - subprocess.CalledProcessError
```

Building the bridge directly shows the real error, four times over:

```
build/solver-bridge/Program.cs(32,28): error CS0246:
  The type or namespace name 'CatShelter' could not be found
```

## Cause

`build/solver-bridge/solver-bridge.csproj` line 12:

```xml
<ProjectReference Include="../../game/Assets/Core/CatShelter.Core.csproj" />
```

That file no longer exists. Creating the Unity project removed the hand-written
`.csproj` from inside `Assets` — which was the **right call**, since Unity claims
that tree and generates its own — but nothing that depended on it was updated.

The reference resolves to nothing, so the bridge compiles with no Core types,
and every conformance test that shells out to it dies.

## The second half, easy to miss

The Core unit tests now run through `game/CatShelter.Core.Tests.csproj`. That
file is **generated by Unity** and matched by `*.csproj` in `game/.gitignore`.
It is not in the repository.

So on a fresh clone there is no way to run the Core tests outside Unity at all.
The suite appears green on a machine where the editor has been opened once, and
does not exist anywhere else. That is precisely the failure mode the
`verify:passed` contract in `tasks/README.md` was written against.

## This was predicted, in writing, before it happened

`AGENT-BRIEF.md`, in the section on task 1.4:

> Two build systems will end up over one set of sources: Unity with its
> generated `.csproj` files, and our `dotnet test`. […] Two ways out. […] Choose
> explicitly and write down why — silently leaving two `.csproj` files over one
> body of code is not an option.

One side of the choice was made — the `.csproj` came out of `Assets`. The other
side, updating everything that pointed at it, was not. And the choice itself was
never written down, so the next person cannot tell whether the current state is
a decision or an accident.

## Not caused by the history rewrite

Worth recording, since the timing invites the assumption. The 390 MB cleanup of
`game/Library`, `game/build` and the stray logs happened after this broke. The
same four tests fail identically on `backup/refactor-difficulty-preclean`, the
untouched snapshot taken before the rewrite: `1 failed, 63 passed, 3 errors` on
both.

## Consequence for the milestone

`10-accounts/04-unity` cannot hold `verify:passed`. Its acceptance requires the
project to build and the tests to run, and from a clean state neither is true.
Set it back to `verify:failed` until this task closes.
